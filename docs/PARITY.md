## 第二轮根因记录

- Electron 多 ClipboardItem 写入的实际系统回读只保留最后一个文件。改用 NSPasteboard 的 NSURL 多项写入/读取，通过两份真实文件的系统 round-trip 验证；不能只靠假对象单测。
- 内联 Pinboard 编辑器在库更新或系统/菜单焦点变化时触发 blur，导致提前提交。保留编辑节点/草稿，将提交限定为 Enter/Escape/Tab 或明确点击其他控件；主动失焦不提交的回归已加入，避免用延时/重试掩盖问题。
- 旧格式、编辑保存与新剪贴板捕获使用不同文本签名，会破坏重新复制后的固定状态。统一正文、HTML、RTF 的签名计算，并覆盖迁移/重启后的重新复制。
- 未保存编辑通过渲染进程 beforeunload 及主进程确认保护，不依赖异步 dirty 通知已先到达。编辑期间切换预览目标会被拒绝，保存失败不关闭窗口。
- 新增预览截图：`test-results/preview-image.png`、`preview-rich-text.png`、`preview-files.png`；快捷键设置为 `settings-shortcuts.png`。全部为合成测试样本，不是原版截图差分。

## 第三轮根因与边界

- 轮询重复读取 PNG、计算签名和解码，主要开销发生在去重判断之前。新增 `src/monitor.js`，先读系统 changeCount，内容读取后再次核对版本；期间新复制、暂停/恢复和自主写入会使旧候选失效。落盘失败不推进版本，可在下一轮重试；启动时不刷新已有内容时间，恢复后新的真实复制仍会记录。
- HTML 经 Electron/macOS 回读会附加精确的 `<meta charset='utf-8'>` 前缀；PNG 经系统剪贴板回写也会更换编码/元数据。前者仅在签名/回写边界去掉已确认的传输前缀，不泛化改写 HTML；后者使用尺寸与解码像素的签名，资产文件保留原始字节。旧图片签名迁移及固定/原图保留已通过真实应用重启验证。
- 富文本由 Tiptap 3.32.0 独立实现，使用现成 ProseMirror 选区/历史引擎，不使用 execCommand。最初的异步 focus 会在输入期间重置选区，已改为同步 EditorView 聚焦；库通知和固定状态变化也不再重建同一编辑器节点。无改动直接关闭，不规范化原 HTML/RTF。复杂表格、嵌入图片等仍未实现无损编辑，当前保护原文并拒绝有损转换，不把该限制当作功能对齐完成。
- 图片草稿按原图和 0/1/2/3 次 90 度旋转建模，调用系统 Core Image/ImageIO，每次从原图生成，缓存至多四种方向、历史只保存方向；四次旋转恢复原始字节。已测透明/半透明像素、旋转方向、撤销/重做、保存失败、取消、保存后原图恢复和固定状态。64 MB/6400 万像素为当前编辑限制；广色域、高位深和大图压力仍待验收。

## 第四轮根因与边界

- 原生图像逻辑拆到 `native/images.m`，使用系统 Vision 文字识别和前景实例掩膜，不自写 OCR/分割算法。系统为 macOS 14.7.8；前景分割仅在 14+ 可用，无模型或无主体返回明确失败，不生成假透明图。图片保留画布，已测中心 RGB 与原图每通道差不超过 2；边缘黄色残留已观察到，头发/玻璃/多主体/复杂版面和其他语言、P3/16-bit、大图未广泛验证。
- OCR 单任务 30 秒，输入 64 MB/6400 万像素，结果限 1 MB/10000 行/20000 词。单队列按 ID+像素签名去重，手动请求优先排队；错误状态缓存但可重试，磁盘写入失败允许重新排队。退出取消任务并等待私有临时目录清理；机密/瞬时图片不进入队列。应用调用本机系统引擎，不上传图片，不能据此推断所有系统模型环境都无需准备。
- 搜索使用当前图片签名对应的 OCR 文本。Vision 词框按可见卡片按需读取，缓存最多 64 份；词匹配优先词框，短语无法对应单词时退回行框，不是精确字形轮廓。全量 JSON 和 OCR 文本仍随库快照传输，尚未解决大库性能。
- 保存成功后后台 OCR 的库通知会再次读取图片草稿；若只清 UI 的 dirty 而不更新服务端基线，已保存图会被误判未保存并触发关闭确认。根因修复为成功落盘后 `ImageDraft.markSaved()`，再排 OCR/通知；保存期间使用 inert 与键盘保护，失败不更新基线。单位测试和真实保存重复 5 次通过，不用延时或自动接受确认掩盖。
- 复制文字必须等 OCR 完成，而等待期间其他复制可能发生。为此在等待前后核对请求序号和 NSPasteboard changeCount，过期请求明确拒绝，不长期占用普通复制队列；无文字不清空剪贴板。测试等待实际系统剪贴板值，而非认为点击已完成异步写入，并在右键复制前设置哨兵，避免旧正确值造成假阳性。
- 图片草稿以 `(turns, backgroundRemoved)` 表示状态，从原图或未旋转前景生成最多八种缓存，历史最多 128 步。恢复背景保留方向，恢复原图清除方向和分割。未来资产回收/迁移必须同时保留 `asset`、`originalAsset`、`foregroundAsset` 及备份引用；当前不回收资产，不声称安全擦除。OCR 是派生缓存，坏/旧缓存丢弃但不能删除图片。
- 分割样本 `test/fixtures/foreground-mug.png` 由内置 image_gen 生成，Prompt/来源见同目录 README；不是原版素材或用户内容。OCR 样本由 Canvas 合成中英文。未新建全局 skill：本轮方法是该项目的状态机和测试约束，保留本记录即可。
- 官方帮助补充线索：[搜索与筛选](https://pasteapp.io/help/search-and-filters)、[粘贴前编辑](https://pasteapp.io/help/edit-items-before-pasting)。其中 OCR、高亮、首次 Return 聚焦结果、CmdE/CmdR/CmdG、内联筛选和模糊/排名进入矩阵；在线帮助可能晚于本机 7.0.2，不是本机界面证据。系统 API 依据本机 SDK，并参考 [Vision 前景掩膜](https://developer.apple.com/documentation/vision/vngenerateforegroundinstancemaskrequest)。

## 第五轮性能与数据格式

- 原始测量发现瓶颈不是虚拟卡片数量，而是每次 `snapshot()` 发送全正文并展开字符数组，`mutate()` 深拷贝整库，随后把完整 JSON 再写一次。现按项复制变更；正文/HTML/RTF/OCR 和内联原图大于 16 KiB 时写入 `contents/<sha256>.json`，私有临时文件 fsync/原子替换并先于清单提交。清单仍全量写元数据，不宣称数据库按行事务已完成。
- 主界面展示摘要最多 2000 字符，大正文不进入常规 IPC，OCR 仅发送可用状态。完整内容留在存储层；长原文末尾搜索、系统剪贴板复制、DataTransfer 完整文本、导出与实际重启通过端到端覆盖。拖动事件必须同步填充 DataTransfer，因此专用同步 IPC 只在拖出时取选中原文，最大 64 MB；失败明确阻止，不用摘要替代原文。真实外部接收仍未验收。
- 搜索使用内置 SQLite FTS5 trigram，不新增搜索依赖；索引在 Worker 内存中，增量同步变更，异常后下一次请求从当前库重建，退出终止 Worker 并拒绝待处理请求。长词走 trigram 候选并用 `instr` 核对；单/双字符退回字面包含，空格分词全部匹配，保留原搜索语义，不把引号/星号/AND 当操作符。输入限 2048 UTF-16 单元/32 词。查询回复携带 revision，UI 另有请求序号，旧回复不能复活旧选中项。
- 数据格式 1/2 在下一次保存时转为 3，原始内联清单以 `library-v2-<sha256>.json` 单独保留，`.bak` 也转换为 3。原因是旧版读取新主文件失败后会尝试旧备份，可能覆盖新历史。已实际加载 Git 提交 `68bfd2a` 的旧 ClipStore 代码验证：新主/备份均拒绝，文件原样保留。新程序遇到未知未来版本停止，不自动降级恢复。目录、contents、assets 和备份引用是整体；这些旧副本均未擦除或回收。
- 故障测试覆盖内容写入失败、清单 rename 失败、缺失/校验损坏内容、备份恢复、元数据/Pinboard 回滚和原图/OCR 保留。清单已经 rename 后若目录 fsync 失败，内存不能回滚到旧值造成文件/运行态分歧；现在保留提交态并明确提示耐久性待确认。这是故障注入，不是真实断电测试。
- 可复现命令：`node scripts/benchmark-store.js 1000`。全部为临时合成数据，脚本结束删除；旧版基线在本轮改动前测得，Node 25.8.0、macOS arm64，1000 项正文约 102 MB。时延不作为跨机器硬阈值；首次拆分、内存与元数据随项数增长仍为缺口。性能报告见下表，实际 Electron 45 / Node 24.22.0 的约 96 MB 索引期间主 IPC 响应另有 E2E 证据。
- API 依据：[Node SQLite](https://nodejs.org/api/sqlite.html)、[SQLite FTS5 trigram](https://www.sqlite.org/fts5.html)。本机 Node 与 Electron 均实际验证内置 SQLite/FTS5/trigram 可用，开发 Node 最低版本提高为 22.13。没有新建全局 skill，本轮不变量保留本记录和测试。
