# Paste Easy

macOS 本地剪贴板工具。当前以本机 Paste 7.0.2 的可见行为为参考重建，**正在开发，尚未达到完整功能对齐、像素级验收或对外发行标准**。实测、差距和下一步见 [docs/PARITY.md](docs/PARITY.md)。使用独立名称与自主实现，不打包 Paste 的程序代码、图标或服务凭据。

## 开发与验证

环境：macOS arm64、Node.js >= 22.13、Xcode Command Line Tools。依赖锁定在 package-lock.json；Electron 45 的剪贴板接口为异步 ClipboardItem。全文索引使用运行时内置的 node:sqlite/FTS5，无新增第三方搜索依赖。

```bash
npm ci --registry=https://registry.npmjs.org
npm run build:native
npm start -- --show
```

默认快捷键 `Command+Shift+V`。与原版 Paste 同时运行时可能被占用，可在设置中更换。自动粘贴通过原生辅助程序激活之前的目标进程并发送 Command+V，需要辅助功能权限；未授权时会复制内容并明确提示，不报告粘贴成功。

`Command+Shift+C` 启动 Stack；两个全局快捷键、Pinboard 导航、快速粘贴及纯文本修饰键均可在设置中调整。支持把卡片拖入 Pinboard、拖动排序；图片/文件卡片悬停时的拖动图标使用原始文件。Space 打开独立预览，原图、富文本与多文件分别显示；未保存编辑会阻止直接关闭或覆盖草稿。

`Command+N`、原生“文件→新建文本”或更多菜单可新建文本，沿用现有富文本/表格编辑器。保存前是独立草稿，不入库、不自动改动系统剪贴板；用户主动复制/粘贴仍按编辑器正常行为执行。关闭空草稿不留记录，未保存内容需确认放弃。正文需含非空白文本，正文/HTML各不超过16MiB；纯图片/无文本的新草稿不会保存为空项目，保留编辑内容并提示。保存失败可原地重试，背景历史/设置变化不关闭或重置草稿。

在明确打开的Pinboard中新建默认固定到该板；搜索状态中新建进入历史，不把筛选条件当写入位置。草稿的固定菜单只临时调整归属，正文与多个Pinboard在同一事务保存；已删除目标需取消或另选，不能静默改存位置。保存后定位到对应项目；内容完全相同时复用既有ID，保留标签、来源、类型和已有固定关系。该能力依据[官方快捷键说明](https://pasteapp.io/help/keyboard-shortcuts)，本机原版新建窗口几何和细节仍待解锁实测。

Stack已接入[官方描述的核心流程](https://pasteapp.io/help/using-paste-stack)：开启后自动收集之后的复制，独立非激活浮窗显示队列、反转顺序和逐项移除，辅助功能权限可用时普通Command-V顺序消费。重复复制同一内容保留独立队列项，失败保留该项并取消尚未开始的后续请求；结束Stack清空临时队列，不删除历史。快捷键再次激活只显示现有队列，不重置。仅复制设置不接管Command-V；权限不足/监听暂停明确提示并保留手动路径，不自动授予权限。最多1000项，快速复制导致变化计数跳跃或归属不明时明确警告可能漏收，不承诺任意速度零遗漏。当前仅通过私有剪贴板、合成按键判定和隔离Electron适配器验收；真实全局快捷键/权限、跨应用消费及本机7.0.2浮窗像素仍待专用时段，不称完整Stack已验收。

`Command+F` 打开全局搜索，包括其他 Pinboard 中的项目。首次 Return 只把焦点移到结果，左右键选择，再次 Return 才发起粘贴；Tab 可在搜索框与结果间切换。识别/搜索尚未完成时不会排队执行稍后的粘贴，重复按键不会连续粘贴、删除或反复开关预览。Escape 先清空查询，再退出搜索并返回原列表。`Command+G` 或右键“在…中显示”关闭搜索，定位并选中所在列表的原项目；仅单选可用。

类型、来源应用、日期和 Pinboard 可组合筛选；活动条件显示在搜索框内，可逐项移除或重置，重置不清掉文字查询。窄屏标签独立滚动，查询框不随标签滚走。输入 `mail link meeting slides` 等内容时会根据实际应用/类型提供候选；只有主动选择后才转换为条件并移除对应词，其他内容仍走字面搜索，不自动解释 URL、引号或操作符。下方向键可进入候选，Escape 从候选回到查询；空查询的 Backspace 先聚焦最后一个标签，再按才移除条件，不删除项目。结果保持历史顺序；Pinboard 筛选也不借用板内自定义排序。

“今天/昨天/最近 7 天/最近 30 天”按本机日历日期计算，包含开始时刻、不包含结束时刻；不是过去 24/168/720 小时。日期条件在本地午夜重新计算，时间比较支持带时区的时间戳。输入法未提交文字只保留在输入框，后台通知仍使用已提交查询。来源项目或 Pinboard 删除后，活动条件不会自动放宽成“全部”，可显式移除；设备维度仍待跨设备同步实现，不显示空开关。

`Command+E` 编辑、`Command+R` 重命名单个选中项目；文件只可重命名。重命名的 Return 提交、`Command+S` 保存编辑，输入法组合期间不执行这些提交/关闭操作。富文本沙箱预览内部聚焦时也可用 CmdE/CmdR，未放宽 iframe 隔离。原生菜单保留系统编辑/窗口操作，不再带有浏览器刷新等开发菜单。上述流程有隔离自动化验证，真实系统输入法、辅助技术及跨应用物理粘贴仍需人工验收。

右键菜单的删除、固定命令绑定打开菜单时的项目和添加/移除意图；后台移除项目或改变选中项时，不转而操作另一项。菜单按键不会继续作用于底层列表，键盘与鼠标执行同一命令。首次打开编辑/重命名窗口会在加载保护解除后聚焦，重命名可直接输入替换原名称。

文本编辑支持粗体、斜体、下划线、删除线、选区格式和撤销/重做，保留已覆盖的字体、字号、颜色和段落/单元格样式。标准 HTML 表格可编辑，支持插入、增删行列、合并/拆分、标题行和 Tab 切换单元格；合并跨度与 CSS 小数像素列宽可跨保存、复制和重启保留，纯文本输出用制表符/换行保留坐标。内嵌 PNG/JPEG/GIF/WebP 可随文字和表格保留原始 data URL，预览也能显示；不会为图片自动联网。未修改或撤销全部修改时不重写原始 HTML/RTF；明确工具命令有独立撤销边界。不带 RTF 的代码、链接、颜色内容仍用纯文本编辑器，避免自动格式化。

含 RTF 的文字记录使用系统 `textutil` 读取和重新生成 RTF，不再进入纯文本编辑后清空格式；同时覆盖仅有 RTF 的旧记录和 Electron/macOS 自动生成 Cocoa HTML 的捕获。有 HTML 时保留其编辑优先级，不强制不同 MIME 表示的正文相同；无 HTML 时才读取 RTF 派生预览。样式表先在禁止脚本/网络的临时文档中由浏览器计算、内联，再经既有净化策略显示/编辑。只有真实修改才同时保存 HTML 与新 RTF；原始字节、ID、Pinboard 和改名在未修改/全部撤销时保留。格式标记不再重复保存在 span CSS 中，关闭下划线等工具后不会残留同样的 CSS 效果。

系统转换通过 stdin/stdout 串行运行，单次10秒、输入/输出各16 MiB、派生缓存最多16项/8 MiB，不创建文档临时文件。HTML 输入明确 UTF-8；保存前核对 RTF 读回正文，只容许系统附加一个段落结束 LF，不 trim 正文。转换失败/正文不一致/迟到回复保留原记录或草稿。已知会丢失的附件、对象、图形、脚注/页眉页脚等 RTF 结构及混合图片编辑暂不支持，不静默删除；此防丢失检查不是完整 RTF/RTFD 解析器。**Cocoa HTML 导出的 generic RGB 与 sRGB 存在预览偏差，尚未修复**；原生 AppKit 已独立验证新保存 RTF 的 sRGB 颜色，但这不证明原始 RTF 到预览像素一致，不能称任意富文本无损。

列表编辑保留显式/隐式起点、倒序、逐项重新编号和嵌套；拆分重新编号的项目时不把该编号复制到新项。保存、纯文本复制与导出保留编号/标记及两空格嵌套缩进，表格格内的列表同样保留标记。使用同版本 Tiptap 列表引擎及 `@jsamr/counter-style` 生成内建标记，不自写罗马/字母计数算法；支持内置数字、字母、罗马和部分国际化样式，不代表全部 CSS 自定义计数器。含自定义计数器/图片标记、未支持样式、非法或超过 signed 32-bit 编号、超过 32 层嵌套的 HTML 会拒绝编辑/粘贴，保留原文，不静默丢格式。主动键入规范的 `0` 至 `2147483647` 后接点和空格仍可创建/续接列表；补零标识符和超范围数字保留为普通文字，不生成无法再次编辑的起点。列表末尾不自动补空段落；表格等结构仍保留原引擎的退出通道，初始化结构归一化不算用户编辑。

粘贴 `text/plain` 时保留连续空行、开头/末尾空段、缩进、制表符和字面 Markdown 符号，不推断为列表、粗体或删除线。新粘贴的 CRLF/CR 按编辑器惯例统一为 LF，不把这条规则用来重写未修改的原始项目。插入保留当前文字样式和代码块上下文；实际 HTML 粘贴仍按安全策略保留受支持的格式、列表、表格和内嵌图，不等于只接受纯文本。

编辑器内复制/剪切只序列化实际选区：表格文字按字符范围裁剪，矩形单元格选区使用引擎裁好的网格，纯文本以制表符/换行保留坐标和合并格的空位，不夹带未选列或重复整张表格。部分有序列表的 HTML 使用原列表中第一项的实际编号，包含隐式倒序起点和逐项重启；复制不修改原文、不产生撤销步骤。一般段落的复制间距保持现有引擎行为；不代表所有跨应用粘贴格式已经验收。

富文本编辑与预览共用独立 DOMPurify 策略，过滤脚本、外部资源、CSS URL/定位和注入应用样式的属性，继续保留无脚本 iframe/CSP。内嵌图片同时检查 MIME 与栅格文件头，完整解码仍由浏览器完成。文档默认黑字白底，不随界面深浅色改变，也不把应用主题写入用户内容。已知无法保留的外部图片、SVG/公式、嵌套/带 caption 的表格、非像素列宽和不完整表格会拒绝编辑/粘贴，原始库内容及当前选区不变，不静默改成纯文本。当前限制：HTML 16777216 个 UTF-16 单元（保存仍受 16 MB UTF-8 限制）、结构 20000 元素、表格网格 20000 格、跨度 100、列宽 10000px、单幅内嵌图 URL 8 MiB；完整 CSS/RTF、更多嵌入内容及高位深/大图内存压力仍待完成，不宣称任意富文本无损。

图片可左右旋转、移除/恢复背景、撤销/重做、恢复原图；保存只更新当前项目，保留原图、固定状态和名称。背景移除调用 macOS 14+ 的 Vision 前景分割，保留画布尺寸与透明度；恢复背景不改变旋转方向。旋转由系统 Core Image/ImageIO 执行，每次从原图或未旋转前景计算，不连续重采样；编辑输入限制为 64 MB、6400 万像素。高位深、广色域及大图压力验收尚未完成；分割边缘可能残色，复杂主体质量尚需验证，不能据此宣称全面无损或精确抠图。

图片自动使用系统 Vision 识别文字，并参与搜索及图片内匹配高亮；预览中可选择/复制识别结果、手动重试，也可从图片右键菜单复制文字。优先中英文语言，单任务 30 秒、结果 1 MB、最多 10000 行/20000 词；失败明确显示，不改写图片。任务按图片版本去重并串行，过期结果不会覆盖新图；识别等待期间发生其他复制时，旧复制请求不会覆盖新剪贴板。应用不上传图片进行识别；系统模型可用性及其他语言/复杂版面准确率仍需验证。

- `check`：所有源码、脚本与测试的 JavaScript 语法检查。
- `test`：存储、迁移、损坏恢复、Pinboard、搜索与保留策略。
- `test:ui`：真实 Electron + IPC。`app.spec.js` 读写系统剪贴板，使用隔离测试数据、不读取已有历史；测试前保存、结束后恢复系统剪贴板。运行该套件前退出其他剪贴板记录工具，可避免其收录测试内容。`media.spec.js`、`media-requests.spec.js`、`rich-lists.spec.js`、`rich-copy.spec.js`、`plain-paste.spec.js`、`rtf.spec.js`、`search-cache.spec.js`、`export.spec.js`、`import.spec.js`、`text-identity.spec.js` 和 `applications.spec.js` 使用隔离合成数据/IPC；应用选择套件另只读系统 TextEdit 的公开应用元数据，不启动所选应用，均不读写系统剪贴板，无需停止原版。富文本/纯文本套件的合成 ClipboardEvent 使用独立 DataTransfer，不访问系统剪贴板。可单独运行 `npm run test:ui -- test/ui/search-cache.spec.js` 或其他独立文件。
- 隔离数据目录不隔离全机剪贴板。`app.spec.js` 启动前检查已知 Paste/Paste Easy/Paste Like 进程，存在未停止的程序或无法检查时，该套件先失败，不启动其测试应用或写剪贴板；其他名称的工具仍须人工确认已退出。可先运行 `node scripts/clipboard-test-environment.js` 检查。第八轮发现原版仍常驻，因此更早的合成测试内容可能已被它收录，未核实或直接清理原版历史；不可把恢复当前剪贴板当作恢复其他应用的历史。
- `test:ui` 运行前自动编译原生桥和编辑器；构建产物也包含编辑器离线包，不依赖 CDN。
- `paste-flow.spec.js` 使用真实主进程 IPC/复制队列和合成写入适配器，覆盖 Stack 连续消费、删除/重建时的迟到请求、失败重试、普通复制穿插、界面错误提示及连续开关预览的原生焦点恢复，不读写系统剪贴板。Stack 成功只移出本次实际处理的队首；重建队列取消尚未开始的旧请求，已开始的剪贴板写入不能撤回。
- 预览延迟失焦只处理当时的窗口、项目状态和调出会话；同窗切换、关闭重开或新调出使旧回调失效，重新聚焦/关闭取消旧计时。执行时仍核对实时焦点和草稿等保护，不是一律禁止失焦关闭。`preview-lifecycle.test.js` 在隔离VM执行实际main.js生产分支/事件计时逻辑，不启动应用或系统适配器；独立Electron回归显式调用同一保护动作，只控制焦点/延迟，并核对真实原生窗口关闭与原文保留，不代表物理桌面焦点或所有原生销毁崩溃已验收。
- `paste-target.spec.js` 覆盖排队/权限等待期间的目标和偏好绑定、前台查询失败清旧目标、乱序打开/快捷键取消、权限/辅助程序失败保留Stack并重试。默认测试模拟之外，该套件显式运行实际投递控制分支，仅替换前台查询、剪贴板写入、权限查询与原生激活适配器，不实际向其他应用粘贴。每次复制在入队前固定目标PID/Bundle ID/启动时间及纯文本/投递偏好；新设置只作用于之后的请求，无法确认目标时保留已复制内容并明确提示手动粘贴。
- 自动粘贴额外绑定写入前的系统变化计数及同一次写入的随机标记；权限等待后、原生激活前和发送按键前核验。剪贴板被替换时取消自动粘贴并保留Stack队首，不把原项目重新写回、覆盖新复制。计数或归属无法确认时只复制并明确提示，不退回无保护自动粘贴。标记不包含正文、目标或库ID，不写入历史/备份；Stack开启时本应用的复制/OCR复制也带标记，以免自己写回后再次入队。其他只复制路径保持既有行为。
- `stack.spec.js` 使用真实队列/监听分发器/浮窗/主进程，仅替换原生传输、剪贴板、权限/目标激活适配器，不注册系统按键监听或读取系统剪贴板；覆盖自动收集/重复、连续Command-V、反转/移除、失败取消后续与重试、权限/暂停/仅复制、未保存草稿和当前目标解析、深浅色/窄窗。`native-stack.test.js` 编译实际事件判定与流式辅助程序，只在命名私有NSPasteboard运行，关闭键盘监听，验证EOF/非法配置释放；合成CGEvent从不发送到系统，不能据此宣称物理按键通过。
- `clipboard-ownership.test.js` 和 `paste-target.spec.js` 的竞争/失败/重试回归仅使用合成适配器；`native-pasteboard.test.js` 编译实际原生保护逻辑，在命名私有NSPasteboard上验证20轮竞争、单次变化计数、多文件原生格式和顺序，不读写系统剪贴板、不发送按键。`app.spec.js` 另有真实Electron富文本/纯文本/图片/多文件归属回归，仍须前置隔离。按键发送前检查不是系统剪贴板锁，也不是目标应用已消费内容的确认；检查后至目标读取之间的极短竞争、真实快捷键/跨应用验收仍未完成。
- `test:packaged`：对构建产物运行同一组端到端测试。

## 数据

正式数据位于 `~/Library/Application Support/Paste Easy/`。首次升级会合并该目录及 `paste-like`、`Paste Like` 的旧 `clipboard-history.json`，按内容去重并保留固定状态；原始文件不修改。不读取原版 Paste 的数据库。

`library.json` 使用 version 3 元数据清单，原子写入并保留 `.bak`。大于 16 KiB 的正文/HTML/RTF/OCR 等内容以 SHA-256 命名的不可变 JSON 文件存入 `contents/`，图片原始 PNG 独立存入 `assets/`；目录权限 0700、文件权限 0600。读取内容时核对哈希；主文件或内容损坏时保留损坏副本并恢复有效备份，无有效备份则停止启动，不用空历史覆盖原文件。原子提交后的目录同步失败会明确警告并保持内存与已提交文件一致，不假报回滚。

启动仍逐项读取、校验侧存内容和文本签名，但校验后仅保留不可变引用、独立展示摘要、字符计数和 OCR 可用状态，不长期持有整库大正文。成功提交的新内容也转换为同样的引用。摘要、改名、Pinboard 和设置变更不重读正文；复制、编辑、拖出和导出按需读取完整内容并再次核对哈希。`getMetadata` 仅供内部元数据读取，`get` 返回完整读取值；写入应使用 `update`、`setOCR` 等事务方法，不能依赖修改读取值来保存。展示摘要以 UTF-16 独立复制，保留 NUL/未配对代理项，不借长字符串切片保留整份正文。

version 1/2 库在读取时保留原文件，下一次成功保存迁移；原始内联库另存为 `library-v2-<sha256>.json`，主文件和 `.bak` 都使用 version 3，防止旧构建自动恢复旧备份覆盖新历史。旧构建不支持新库，不应混用；新程序遇到未知更高版本也停止，不降级恢复。迁移副本、旧内容与原始图片均未自动回收，尚未实现静态加密或安全擦除。完整备份必须包含清单、`contents/`、`assets/` 及需要的备份引用，不能只复制清单。

删除历史保留 Pinboard 中的项目；删除 Pinboard 不删除其项目。正在编辑的项目在窗口关闭前免于自动到期/容量清理和清空历史，显式删除会被拒绝。历史期限变更立即执行，固定内容豁免。`PASTE_DATA_DIR` 可指定隔离数据目录；`--test-mode` 关闭自动监听与全局快捷键，仅用于开发验收。

监听按系统剪贴板变化计数读取内容；未变化时不重复读取/解码图片，读取途中变化会丢弃旧候选并重试。暂停期间不补录，设置保存和自主复制分别串行执行。HTML 签名忽略 Electron 添加的已知编码前缀；图片按尺寸与解码像素识别，旧图片记录首次升级会一次性迁移签名，保留 ID/固定状态和原始文件。

隐私页可通过原生选择器一次添加最多32个 `.app`，显示本机应用名称/64px图标，并按 Bundle ID 去重和排除；已移动/卸载或无法定位的规则保留原标识，仍可移除。“按标识添加”保留旧配置和未安装应用的高级入口。名称/图标仅为本次运行的有界元数据缓存，设置/备份仍只保存标识，不存应用路径或图标，不启动所选程序。添加/移除在现有设置队列中基于最新值执行，选择器晚返回和连续操作不会恢复已移除的规则；查询的迟到回复不复活旧行，取消/校验/保存失败保留原设置。

每次新复制重新读取前台应用身份，不再复用800ms缓存或把之前应用当成当前未知来源；来源读取失败保持该次捕获可重试。未变化的剪贴板仍不读来源。排除基于捕获时能识别到的前台 Bundle ID，不是后台剪贴板真实写入者的完整归因或系统级DLP；物理切换/后台写入仍需人工矩阵验证。新增规则不追溯删除既有历史、备份或缓存，也不等于加密/安全擦除。屏幕共享遮蔽仍未实现，不能用未验证的开关或单独一次系统API调用宣称隐私保护已完整对齐。

文本身份由原生 `JSON.stringify(['text-v2', body, htmlPayload(html), rtf])` 的 SHA-256 决定，正文/HTML/RTF 有明确字段边界，未配对 UTF-16 单元转义后再哈希。旧版直接拼接 `text:...\nhtml:...\nrtf:...` 会让嵌入相同分隔符的不同内容碰撞，直接 UTF-8 编码还会把不同未配对代理项变成同一替代字符，导致重复制/旧目录合并/备份合并误覆盖。新算法保留已知 HTML 传输前缀归一化，正常内容、字段原文、ID、改名、成员和排序不改；启动按既有加载流程重算文本签名，不因仅打开库就写回清单，不在加载时按签名合并记录。后续成功事务写入新签名，旧版本迁移原件/备份和原始内容文件保留；`text-v2` 是内部身份域，不是库或导出格式版本。不要降级回旧算法构建写回新库；本次修复不能凭空重建已经被旧逻辑覆盖的原文，是否有可用历史副本须另行核实，本轮未扫描真实用户历史。

原记录仍按 UTF-16 保留，复制时按系统 Unicode 标量传输规则使用 `toWellFormed()` 输出，未配对代理项变为 U+FFFD，空格式不伪造 HTML/RTF。监听器记住实际写出字段的签名，避免自主复制非法 Unicode 或空格式记录后反复收录；计算不读回剪贴板，因此不会误把稍后外部写入认成自主复制。该规则不改存储/备份原文，不代表任何非法 UTF-16 都能经第三方应用无损传输。

主面板仅接收最多 2000 字符的展示摘要，不接收大正文/HTML/RTF/OCR 全文；复制、拖出、编辑和导出仍取完整内容。图片预览和来源图标在常规库通知中只传内容哈希引用，按可见卡片与邻近预取范围批量读取，相同图标复用。缩略图最长边 480px、图标 128px，保持比例且不放大小图，不修改原图；主进程和界面各保留最多 96 份、16 MiB 编码数据的 LRU 缓存，最多两个界面请求并行。缓存限制不等于解码图片或整个应用的内存上限。旧图片回复不能覆盖新版本，损坏预览显示不可用而不删除原记录；原图仍可独立预览/复制/导出。

媒体空回复只约束原请求的项目/库版本/面板会话，不封锁后来重新收录的相同图片。临时 IPC 错误在 250ms、1000ms 后最多自动重试两次；仍有效的同一媒体键在多个卡片间共用预算，不因来源图标的请求者轮换或后台通知而形成忙循环。用尽后显示不可用，重新打开面板可开始新一轮恢复；不为搜索中已隐藏的卡片执行计划重试，成功后保留原图并清除媒体错误提示。该策略不等于挂起请求超时取消或原生同步解码故障恢复。

全文搜索仍在工作线程的 SQLite FTS5 trigram 索引中执行，结果带库版本以拒绝过期响应；支持中英文、单/双字符、字面标点与多词组合，不把输入当 SQL/FTS 语法。正式应用使用 `search-cache/index.sqlite` 的私有派生缓存，首次搜索从当前原文同步，重启可复用未变索引。侧存内容仅传引用与查询元数据，由工作线程逐项读取并校验，不在主线程读取或通过首次消息传输整库正文；工作线程也不先展开全部原文集合。尚未迁移的内联项目仍直接传正文。索引差异状态仅保存摘要指纹，SQLite 页缓存建议为 8 MiB，不是 Worker 或整应用内存上限。查询仍限 2048 个 UTF-16 单元、32 词。

缓存目录权限 0700、数据库及 WAL/SHM 为 0600。重用前检查缓存版本与 FTS 外部正文一致性，并逐项核对当前原文的规范化字节，不能仅凭缓存自带指纹跳过同步；损坏缓存可从原库重建，初始化遇到文件锁、路径/写入失败或未知版本时回退内存搜索，不修改原库。该缓存及其日志包含未加密的规范化正文/OCR/备注等搜索内容；删除、到期或离线修改后在下次搜索同步，不代表即时清除全部副本或安全擦除。它不是备份，完整恢复不依赖该目录；隐私/容量管理必须考虑它。启动全量校验 IO、首次磁盘建索引、旧内联库首次拆分/快照克隆、大单项 payload、持续运行/总内存、全量元数据、媒体去重和资产回收仍待优化。

`benchmark-restart.js` 在临时合成库落盘后启动两个全新的 Node 子进程，分别测量重开原库、快照和首次全文查询的时间/内存，第二个进程可观察缓存复用。未清空 OS 文件缓存、未强制 GC，Worker 的 RSS 为全进程指标，不能相加或当作正式 Electron 应用性能验收。

`benchmark-electron.js` 需要先构建当前开发包；用独立合成库连续启动两次真实产物，报告面板就绪/首次查询及主进程和各子进程内存，不读写系统剪贴板。各进程工作集含共享页面，不能相加为独占物理内存；一次合成观测不代替持续运行、真实用户库或完整性能验收。

导出 JSON 包含当前图片、可恢复原图、已有前景图和完整文本/HTML/RTF/OCR，保持 version 2 交换格式；文件类型项目保留原路径引用，不是原文件内容备份。正式文件导出在独立 Worker 中逐项读取/校验，使用原生 JSON 序列化和有背压的写入；图片按块计算校验和并编码 base64，不把整库或全部图片变体展开到内存。额外内存仍包含元数据快照和最大单项文本 payload，不是固定 64 KiB 上限；旧内联库/大媒体元数据仍有初次克隆开销。内部 `exportData()` 兼容接口仍展开整库，不能当大库文件导出路径使用。

设置页显示导出进度并可取消；仅允许一个导出任务，应用正常退出会取消并等待工作线程清理。导出对应任务启动时的快照，并发改名/删除不会混入新状态。完成并同步 0600 临时文件后才原子替换目标，再同步目标目录；提交前失败/取消保留旧导出，提交后目录同步失败报告已导出但耐久性未确认。已提交后到达的取消不会撤销新备份；意外进程退出且无法确认提交状态时要求检查目标，不假称旧文件必然保留。源内容/图片损坏或缺失拒绝导出，库清单/内容资产/内部索引、恢复暂存区与恢复前备份等受保护路径（包括符号链接父目录）不能被用户导出覆盖。硬崩溃/断电仍可能留下私有临时文件，不代表完成备份。

设置页“恢复备份”读取本项目 version 1/2 JSON 或旧版项目数组，不是原版 Paste 数据库导入器。独立 Worker 使用固定版本 `@streamparser/json` 分块解析，逐项验证并写入 0700 暂存目录；校验完成前不修改当前库。拒绝重复/危险 JSON 字段、未来版本、错误类型/成员/设置、外部内容或图片资产引用。PNG 由 Electron 解码、核对尺寸、重新计算像素签名并生成预览；不信任备份自带签名/缩略图，保留原 PNG 字节和有效 OCR。文本/HTML/RTF、稳定 ID、Pinboard 成员/顺序及原图/前景图可恢复；文件项目只保留合法 file URL，不读取或自动打开所指文件，不恢复其实际内容。

预览默认“合并”：同内容沿用当前项目及改名、合并板成员；相同 ID 的不同内容/不同 Pinboard 生成新 ID，不覆盖现有内容。也可明确确认“替换”，仅保留备份内容。默认保留当前偏好，另行勾选才恢复快捷键/隐私排除等设置。恢复提交本身不按保留期限/容量裁剪，后续正常记录与设置变更仍应用既定策略。预览后库有变化或正在编辑时拒绝提交，须重新选择并确认。

外部备份使用 `history` 作为 Pinboard ID，或 ID 含控制字符/未配对代理项时，按类型和原始 UTF-16 内容生成安全、确定性的替代 ID；同时映射项目、板成员及手工排序，已有正常 ID 不变，也不覆盖原备份中恰好占用该替代 ID 的项目。预览显示修复数量，重复导入同一输入不会仅因重新修复标识而创建新板。图片恢复还核对原图/前景/当前尺寸及旋转状态，并用现有系统旋转算法重新计算预期像素签名；不一致时拒绝整个备份，保留当前库，不擅自删掉原图或改变编辑状态。内嵌 PNG 内容优先于空资产占位字段，避免原图或前景图被空值覆盖。取消/Worker 故障会中止并等待委托的图像校验结束，再清理暂存；正常旋转验证不传输重复缩略图。

提交前先将当前库导出为私有、可独立恢复的 `backup-before-import-UUID.json`，再校验/同步并链接不可变资产，最后通过现有原子清单事务切换。提交前校验/写入/取消/快捷键失败保留原库；提交后目录同步或运行设置更新失败明确报告已恢复及警告，不假称回滚。设置页可在本次运行中定位恢复前备份；备份文件跨重启保留，可再次选择恢复。退出等待任务清理，失败可重试；硬崩溃可能留下暂存目录、恢复前备份及未引用不可变资产，尚无自动清理/备份管理或安全擦除。

导入当前限制：文件 8 GiB、100000 项、1000 个 Pinboard、深度 64；单项原始 JSON 约 384 MiB、解码字符串 90 MiB、文本/HTML/RTF 各 16 MiB、PNG 各 64 MiB/6400 万像素、展示记录合计 64 MiB，另有限制头部/板/标记大小。解析保留最大单项和展示元数据，不是固定 64 KiB 内存；来源图标只做有界内嵌格式检查。十万项/极大图片/低磁盘/真实断电压力、手动原生文件选择器和恶意并发文件替换尚未全面验收。备份/暂存均未加密，恢复前备份包含原库全文；隐私管理不能忽略这些副本。

恢复 PNG 的读取、原始 SHA-256、完整解码、规范像素签名与缩略图改由独立内部 renderer 串行处理，主线程仅发送私有文件路径并接收尺寸/签名/预览，不复制原始 PNG 或全幅像素到 IPC。继续使用 Electron nativeImage 的同一解码/像素规则，并复用已解码图片，不改为 PNG 字节去重或缩小原图；旋转由主进程管理现有原生辅助程序，在 0700 临时目录复制并校验 0600 输入快照，再校验输出尺寸/像素，取消及退出等待处理与清理。读取先检查普通文件/64 MiB，拒绝符号链接并按已观察大小有界读取；解码前再检查 PNG 头部与6400万像素上限。

校验 renderer 只加载空白本地页面：CSP 禁止内容/脚本/网络、禁止导航/弹窗/webview，不向页面暴露 API；独立内存 session，不加载备份 HTML。为 nativeImage 的 Node Buffer 接口使用 contextIsolation=true、nodeIntegration=false、sandbox=false 的受信 preload；这是响应性隔离，不是恶意图像解码的操作系统安全沙箱，正常应用窗口仍保持原有沙箱设置。回复须来自当前窗口主 frame 和当前请求；30 秒超时、取消、崩溃或退出销毁该会话并拒绝结果，下次可新建；闲置 1 秒释放校验窗口。独立进程有启动和额外内存成本，不能只看主进程 RSS 宣称整应用内存降低。其他图片捕获/预览/迁移/复制仍有主线程工作，本次不代表全部图像路径、极大图或长期压力验收。

`benchmark-export.js` 在全新 Node 子进程测导出耗时、响应心跳和进程 RSS/峰值，之后再完整解析 JSON 核对内容。导出采样与验证峰值分别报告；独立完整解析自身消耗较多内存，因此脚本限 1–2000 项，不是应用导出数量上限。无强制 GC/OS 缓存清理，不能把种子或后续校验内存当成导出额外内存。

`benchmark-import.js` 逐项生成合成 JSON 后启动全新子进程，分别测校验/预览和提交耗时、2ms 心跳与 RSS/峰值；不完整解析备份，采样后逐项核对完整原文，并重开库再核对全部项目。Node Worker RSS 已包含在进程内，不能相加；仅合成文本，不等于真实 Electron 总内存、图片或持续运行验收。

`benchmark-import-images.js [width]` 需要当前开发包，默认2048×1536；使用分开的种子、导入和重启进程，对八种旋转/背景状态的当前/原始/前景 PNG 校验和逐一核对，测真实主进程准备/提交时间、2ms心跳最长间隔及 RSS，并报告各进程工作集快照（含校验 renderer）。共享内存不能直接相加为独占物理内存，原生辅助进程峰值未采样。只用合成图片，OCR 缓存为无文字以隔离恢复路径，不读写系统剪贴板；不是全应用/长期或任意单项/6400万像素压力通过。

OCR 缓存保存在同一库中，绑定当前图片签名，图片改变后重新识别；行/词定位按需读取，不在每次全库通知中传输。项目 `.npmrc` 和锁文件使用公开 npm registry，已通过独立缓存的重新安装；审计也必须使用公开库。本机全局默认镜像的零漏洞结果不能代替公开漏洞库，构建依赖仍有 8 项 moderate。

## 构建与发行

`npm run build` 生成 `release/mac-arm64/Paste Easy.app`，仅使用 ad-hoc 开发签名。构建后必须通过真实产物测试；**开发签名不等于 Apple Developer ID，也不代表通过 Gatekeeper 或可以对外发放**。

发行构建使用 `npm run build:release`，必须提供 `CSC_NAME` 对应的 Developer ID Application 身份，以及 Apple notarization 凭据：API Key 三项 `APPLE_API_KEY/APPLE_API_KEY_ID/APPLE_API_ISSUER`，或 `APPLE_ID/APPLE_APP_SPECIFIC_PASSWORD/APPLE_TEAM_ID`。凭据不写入仓库。

`release:verify` 顺序验证 codesign 完整性、Gatekeeper、stapled notarization，任一失败均返回非零。当前机器缺少 Developer ID 身份，尚不能生成合格发行版。不要关闭 Gatekeeper、清除隔离属性或对已被撤销的旧包重新签名来代替发行验证。

## 代码入口

- `src/main.js`：窗口、监听、IPC、原生粘贴与设置。
- `src/paste-target.js`：不可变目标身份、异步调出会话、权限/激活失败的已复制状态；不替代原生目标身份校验。
- `src/clipboard.js`：同一次剪贴板读取中的文本、HTML、RTF、原图和文件格式。
- `src/monitor.js`：变化计数、异步读取失效、暂停边界和自主复制抑制。
- `src/editor-entry.mjs` / `src/image-editor.js`：Tiptap 基础富文本编辑、系统图像处理与非破坏性图片草稿。
- `src/rich-content.mjs`：富文本净化、嵌入图边界、表格网格/列宽规范化与纯文本坐标序列化。
- `src/rich-text.js` / `src/native-rich.mjs`：系统 RTF 转换、正文校验、生命周期/缓存与隔离样式表内联。
- `src/image-text.js` / `native/images.m`：版本化 OCR 队列、系统 Vision 识别/分割与 Core Image 处理。
- `src/preview.*` / `src/transfers.js`：独立预览、受隔离的富文本显示、原始文件拖出与系统分享。
- `src/store.js` / `src/model.js`：原子存储、迁移、Pinboard 与搜索策略。
- `src/content-files.js` / `src/search*.js`：不可变内容文件、工作线程全文索引、增量更新和失败恢复。
- `src/media.js`：媒体内容引用、可见范围取图、有限缓存和双轴缩略图生成；不改存储格式或原始图片。
- `src/renderer.js` / `src/styles.css`：虚拟横向卡片、搜索、多选、预览编辑与 Stack。
- `src/search-filters.js`：元数据候选、可见筛选条件、本地日历范围；不修改全文检索语义或结果排序。
- `src/settings.*`：独立设置窗口。
- `native/bridge.m`：前台应用、原生图标、辅助功能状态与明确目标的粘贴。
- 文件剪贴板使用原生 NSPasteboard 多项 URL 读写；不依赖只保留最后一项的 Electron 多文件写入路径。
